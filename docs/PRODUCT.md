## 1. 产品是什么

OraSage 是一套文化自我探索站点：用传统历法与牌阵做结构对照，用五行器物把意向做成可以佩戴、赠送的实物，用门户文章把这些传统讲清楚。

一句话：**排一次盘或翻一次牌，得到一份可回看的解读；想把意向带在身上，就在商城选一条五行手串。**

八个应用各自一个子域名，共用一套账户。用户看到的是一个站，工程上是八个可独立打开、可各自安装到手机或平板主屏幕的 Web 应用。

| 子域名 | 应用 | 用户看到的名字 | 打开后的第一页 |
|--------|------|----------------|----------------|
| `orasage.com` | 门户 main | OraSage | `/zh-CN`（默认语言） |
| `shop.orasage.com` | 商城 | 商城 | `/` |
| `auth.orasage.com` | 账户 | 登录 | `/login` |
| `bazi.orasage.com` | 八字 | 八字 | `/` 经典罗盘 |
| `ziwei.orasage.com` | 紫微 | 紫微 | `/chart` |
| `tarot.orasage.com` | 塔罗 | 塔罗 | `/` |
| `admin.orasage.com` | 运营后台 | 后台 | `/`（需运营角色） |
| `cms.orasage.com` | 内容管理 | 内容 | `/admin` |

安装名称与说明写在 `shared/pwa/install-manifest.ts`。每个来源单独一份清单，`display: standalone`，范围是该来源的 `/`。从已安装的八字点到商城，会离开八字这个应用窗口，进入商城自己的窗口或浏览器。这是子域名架构下的正常行为。

## 2. 给谁用

面向想用传统文化做自我对照的成年人，以及选购、赠送五行手串的人。门户同时服务中文、英语、巴西葡语读者。

产品语气是文化参考与日常提醒。水晶是象征物和心理锚点。解读是算法根据公开历法模型生成的文本。页面上的功效、运势、疗愈承诺由文案检查脚本拦住（见第 4 节）。

紫微对未满 16 周岁的出生日期有单独内容边界：仍可排盘，解读只保留基础命格、健康、学业与未来方向，并收起水晶推荐卡。

## 3. 信息架构

顶栏（以及平板左侧轨、手机折叠菜单）使用同一套栏目。中文与英文对照：

| 中文 | English | Português | 去哪里 |
|------|---------|-----------|--------|
| 首页 | Home | Início | 门户首页 |
| 商城 | Shop | Loja | `shop.orasage.com` |
| 玄析 | Insights | Insights | 门户 `/insights` |
| 造物 | Origins | Origins | 门户 `/origins` |
| 测算 | Readings | Leituras | 门户 `/readings`，再进入三个测算应用 |

商城与玄析没有第二级菜单。造物的子项：造物记、工坊、缘起。测算的子项：八字、紫微、塔罗牌、名人案例、道藏，以及「我的测算」。

壳层文案还保留繁体标签，供壳组件在 `zh-TW` 键上取词。门户路由本身只接受三种现行语言，见第 12 节。

## 4. 内容边界

全站页脚带娱乐用途声明。标准表述（中文）：

> OraSage 的八字、紫微斗数与塔罗解读，以及我们的水晶内容，均为文化娱乐与自我探索工具，不构成医疗、财务、法律或人生决策建议。结果由算法基于公开历法模型生成，仅供您参考。

声明有五种篇幅，按场景选用（`shared/app-shell/disclaimer-copy.ts`）：

| 变体 | 用在 |
|------|------|
| compact | 空间紧的页脚短句 |
| standard | 普通页面 |
| full | 测算结果页，含医疗 / 财务 / 命运定论三条 |
| product | 商品页：文化符号说明 |
| transaction | 结账：购买的是文化饰品与娱乐内容服务 |

名人案例另加一句：人物解读来自公开出生资料，是文化演绎，既非已核验命盘，也不代表本人观点。

`scripts/lint-claims.mjs` 扫描商品与测算文案，拦住疗效和迷信承诺，例如「招财」「辟邪」「开光」「能量手串」、英文 attract wealth / chakra / good fortune。水晶文案的合法说法是五行意象和日常提醒（生长、行动、稳固、静定、边界），并写明「文化意象，非疗效承诺」。

八字解读写作另有硬规则：禁止医疗、财务、法律建议；身弱只写「偏耗」；术语放在句尾。详见 [`BAZI-REPORT-PRODUCT.md`](BAZI-REPORT-PRODUCT.md)。

## 5. 一条完整的用户路径

```
门户首页
  → 测算：八字 / 紫微 / 塔罗
  → 得到可回看的结果（静态报告、命盘或牌阵记录）
  → 需要详版时进入商城结账
  → 支付完成，同一份结果变成详版
  → 「我的」里能再找到测算、订单、推荐与档案
```

实物路径平行存在：

```
商城或塔罗水晶页
  → 五行手串 / 礼盒 / 自组手串
  → 购物车 → 结账（需要地址与手围时才收集）
  → 订单出现在门户「我的订单」和运营后台
```

内容路径：

```
玄析（日主、五行、节气、水晶志、勘误）
造物（造物记、工坊、缘起）
道藏与名人案例（挂在测算栏目下）
```

门户首页同时放三块：测算入口、商城精选、内容入口（名人案例、道藏）。已登录用户可使用站内客服对话；未登录时对话入口固定在右下角。

## 6. 账户

账户中心在 `auth.orasage.com`。注册、登录成功后签发 JWT，Cookie 名 `orasage_token`，域 `.orasage.com`。八个应用认的是同一份登录态。

三个测算应用在这份 Cookie 之外，仍保留各自原来的进入方式：

| 应用 | 认到 OraSage Cookie 时 | 同时保留 |
|------|------------------------|----------|
| 八字 | 映射为 openId `orasage:<用户>` | 原有 OAuth |
| 紫微 | `/api/auth/me` 返回登录用户 | 无 Cookie 时整站匿名可用 |
| 塔罗 | 用 `User.externalId` 桥接 | 访客身份 |

本地用 `http://127.0.0.1` 调试时，Secure Cookie 不会留在该主机上。接口测试改用登录 JSON 里的 `token`，放进 `Authorization: Bearer`。

游客可以先排盘。八字游客记录的 `userId` 为 0；付款人可以认领自己这次的盘。别人的盘不能被认领。

门户「我的」包含：档案、我的测算、推荐、订单、功德、设置、工单，以及关于、联系、隐私、条款。

运营角色（后台门禁）为 `admin`、`shop_ops`、`content_ops`。普通用户 JWT 进不了后台。

## 7. 八字

入口：`https://bazi.orasage.com`。细则以 [`BAZI-REPORT-PRODUCT.md`](BAZI-REPORT-PRODUCT.md)（2026-10-05）为契约，这里只保留产品结论。

**一次排盘，一份报告。** 免费时标题是「你的结构速览」；付费后同一条链接、同一个 HTML 文件变成「你的命局解读」。

五条硬规则：

1. 经典罗盘（`/`）和计算器（`/classic`）调用同一套 `calcSingleBazi`。合盘是两个人各算一次再合成。界面不同，四柱必须相同。`/luopan`、`/scene` 回到 `/`。
2. 用户看到的第一段正文来自网络 AI 简版。本地模板 `composeFreeReport` 只用于测试和命盘旁的结构说明（日主行、网格 caption）。四柱与五行雷达先本地起盘，再由同一次 AI 校准，页面以校准结果为准。
3. 先看简版，再付费看详版。详版是同一文件上的七章全文，另附周运时间轴。
4. 一排完就写入 `user_readings`，并落成静态 HTML。身份是输入指纹加上账号（或设备号）以及请求 IP。相同条件再打开，直接用这份文件。
5. 付费 SKU、回跳、语言、分享沿用既有契约。

报告编号：已登录 `bazi_u{userId}_{fingerprint}`，游客 `bazi_d{deviceId}_{fingerprint}`。公网地址形如 `https://bazi.orasage.com/reports/reading_….html`，打开链接本身不要求登录，便于分享。生产文件在 `/var/lib/orasage/bazi-reports`，部署不会把它清掉。

报告页主按钮只卖数字详版 `report-bazi-basic`，结账回跳必须回到带 `paid=1` 的计算器页，并等到页面出现 `data-report-tier="paid"` 再打开。手串套餐 `report-bazi-advanced` / `report-bazi-premium` 以及合盘三档在商城仍可购买；付费后报告层做的是同一件事（把该 reading 写成 paid），手串另走发货。

## 14. 支付与订单

默认支付模式是 `mock`，开发和生产都一样，便于把下单、回跳、解锁报告走完。要收真实款项时设置 `PAYMENT_MODE=stripe`，并配置 `STRIPE_SECRET_KEY` 与 `STRIPE_WEBHOOK_SECRET`。只有模式为 stripe 且密钥存在时才走 Stripe。

数字报告支付成功后，商城通知对应测算应用把那份结果写成付费版，并把订单标完成。八字这条链路的细节见报告契约：回跳页必须等到付费标记，超时就提示稍后刷新。

实体商品走收货地址与发货。运营在后台处理订单、配送、促销、评价。

销售渠道在后台建好之后，商城链接带上 `channel=渠道编码`（例如 `https://shop.orasage.com/?channel=br-sao`，结账链接同样可以带）。商城记住这个编码 30 天。创建订单时，编码对应一个启用中的渠道，订单就记下这个渠道，后台订单列表能看到。编码不存在或渠道已停用时，订单照常创建，渠道列为空。分成仍在渠道成员上配置，这一步只把订单归到渠道，不自动打款。

## 15. 运营后台与内容管理

后台 `admin.orasage.com` 给 `admin` / `shop_ops` / `content_ops` 使用。现行页面包括：

- 总览、分析
- 订单、商城订单、配送、促销、评价、类目、标签
- 商品编辑、商品内容、水晶首页、手串 DIY
- 测算记录
- 渠道及渠道详情
- 钱包及用户钱包
- 账单、财务
- 员工
- 站内消息与 IM

`/beads` 转到 DIY 管理。

内容管理是 Payload（`cms.orasage.com/admin`）。商品长页、图片、视频、证言从这里进商城详情。首次打开会要求创建内容管理员。业务表在 PostgreSQL 库 `orasage_cms`。

账户与订单主数据在 `orasage_auth`。八字在 `orasage_bazi`。塔罗在 `orasage_tarot`。

## 16. 品牌与视觉

共享品牌图标在 `shared/brand/`。安装图标用 `favicon/icon-192.png` 与 `icon-512.png`。各测算的深色子品牌标（黑底深色图形）对比度不够，不用作主屏幕图标。

视觉规范的历史版本在 `docs/design-system/`。全站壳层的颜色变量以 `shared/app-shell/` 现行样式为准：菜单与平板轨使用不透明底（`#ffffff`，可被 `--shell-menu-bg` 覆盖）。

## 18. 现行范围摘要

截至 2026-11-03，产品包含：

- 三种门户语言：简体中文、英语、巴西葡语
- 三个测算：八字（罗盘与计算器、简版/详版同一份 HTML）、紫微（单人与合盘、对话额度、知识与书库）、塔罗（单牌、三牌、每日、祈福、许愿、梦境、天使牌、水晶浏览、功德）
- 商城：五行手串与礼盒、数字报告、对话加量、祈福乐捐、购物车、结账、地址、DIY、礼赠
- 一个账户打通八个应用
- 运营后台与内容管理已是可用的操作台，商品详情内容从 CMS 进入商城
- 支付默认模拟；Stripe 由环境变量打开
- 手机折叠菜单、平板左侧导航轨、桌面顶栏；八个来源都可安装到主屏幕
- 页脚与结果页的娱乐用途声明，以及文案承诺检查

数据库均为 PostgreSQL：`orasage_auth`、`orasage_cms`、`orasage_bazi`、`orasage_tarot`。紫微不单独建库。
